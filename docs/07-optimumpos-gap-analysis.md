# OptimumPOS Gap Analysis

## What The Current Packaged Setup Appears To Do Well

Based on the observed `C:\kassa` pattern:

- simple packaged Windows deployment
- local-state resilience through backups and logs
- straightforward updater model
- existing payment-provider integration traces
- stable daily cashier operation without developer tooling

## What Atlas POS Must Match Before Replacement Is Credible

- packaged Windows reliability
- terminal identity and trust
- printer compatibility
- payment-provider compatibility
- offline tolerance
- supportable logs and evidence
- clean receipt output
- predictable update path

## What Should Stay Bridged In V1

- opaque incumbent order/export flows where direct replacement is not yet justified
- Worldline-adjacent legacy provider handling where bridge logic is enough
- unsupported or uncertain hardware estates

## Biggest Replacement Risks

- hardware surprises
- payment-terminal edge cases
- hospitality workflow nuance
- staff retraining
- rollback complexity

## V1 Rule

If Atlas POS cannot clearly beat the incumbent on:

- supportability
- visibility
- sync discipline

then it should not be sold as a replacement yet.
